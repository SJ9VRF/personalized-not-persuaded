02 · Why this problem matters

Personal context can help — and still be the wrong evidence.

A personal AI should use your preferences, goals, constraints, memories, and tool results. But those signals do not all deserve the same influence. The hard problem is deciding when context may change presentation, planning, personalization, or the factual state of the answer.

The problem

Explicit user statements and memories feel authoritative because they are personal. A naive system can silently turn “the user believes X” into “X is evidence.”

Why it is hard

The same content can be valid evidence in one task and irrelevant in another. A calendar fact may matter for planning but should not prove an unrelated world claim.

Why simple methods fail

Naive personalization leaks unsupported influence. Fixed firewalls prevent leakage but starve the system of legitimate verified or personal-state evidence.

03 · Core idea

Give each user signal standing, not blanket authority.

PLP learns a task-conditioned standing vector from scope × provenance × confidence × currentness × relevance. A signal can have standing for presentation or personalization without having evidentiary standing.

Personal relevance ≠ evidentiary authority. Influence should be permissioned.

Novelty

The project reframes personalization as a task-conditioned evidentiary-standing problem and evaluates two failures jointly: unsupported influence leakage and evidence starvation.

Three independent licenses

  • Presentation — wording/style may change
  • Personalization — recommendations/priorities may change
  • Evidentiary — the signal may alter the answer’s evidence state

08 · Failure analysis

Concrete benchmark failures reveal two opposite mistakes.

Case 0 · User belief becomes world evidence

Task: factual-world judgment.

Signal: explicit user world claim.

Expected: not evidentiary.

Naive: licenses it because it is explicit and personal.

PLP recovery: blocks evidentiary influence; personalization may still change presentation.

Case 6 · Personal state leaks into unrelated fact

Task: factual-world judgment.

Signal: explicit personal-state statement.

Expected: irrelevant to the world claim.

Naive: treats personal relevance as authority.

PLP recovery: scope mismatch blocks evidence use.

Opposite failure · Evidence starvation

Case family: tool-verified or current personal-state evidence for a matching task.

Fixed firewall: blocks the signal because it came through memory/profile context.

PLP recovery: provenance + task match grants an evidentiary license, while stale/low-confidence/conflicting signals route to verification or human escalation.

10 · Scaling

What has been measured — and what has not.

Model size

The licensing layer is lightweight and model-agnostic. This release evaluates a learned linear router and rule-based baselines. Language-model scaling is outside the current experiment.

Task horizon

Long-horizon stress infrastructure contains 960 measurement points spanning up to 200-turn synthetic trajectories.

Tool count

Tool provenance is represented. A production study should vary the number, reliability, and conflict structure of tool outputs.

Cost / latency

Hybrid PLP measures ~33.0 µs/item median in batch routing over the 912-case domain-OOD split on the local CPU. This excludes generator, tool, network, and serving overhead; end-to-end cost/latency remains an external deployment measurement.

Robustness

Behavior stress tests vary social pressure, profile richness, language, memory, and contradictory preferences.

Data scale

4,800 ProvenanceBench examples + 800 paired provenance interventions, with 1,200 behavior scenarios and 4,920 profile-conditioned contracts retained as supporting stress tests.

11 · Safety / limitations

Evidence permission is not action permission.

Still fails / unresolved

  • Provenance spoofing or compromised tools
  • Ambiguous mixed-scope signals
  • Stale personal state if currentness is wrong
  • Generalization beyond the controlled generated benchmark is not yet demonstrated
  • Frontier-model and real-user longitudinal results are not yet measured

Permission boundaries

  • Irreversible external actions need separate authorization
  • High-stakes ambiguity should trigger verification
  • Conflicting provenance should not be silently resolved by preference
  • Human escalation remains necessary where evidence or authority cannot be established
12 · Technical deep dive

From licensing prediction to an eval-to-training loop.

The current system uses a learned three-head license router plus narrow validity gates. The engineering loop does not stop at evaluation: failures are converted into targeted correction examples, paired with stability anchors, and sent back through the same frozen evaluation surface after a future training intervention.
